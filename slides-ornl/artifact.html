RQ3 · DATA

The classical–quantum data interface

Loading N values needs Θ(N) CNOTs even with a vectorized QCrank-style loader, and reading n-qubit correlations back by tomography needs O(n²) measurements. If the interface is not structured and learnable, no learning model built on top of it is shot-efficient.

RQ5 · TRUST

Trust on shared cloud QPUs

A fixed, public error-correction encoder gives a co-located fault-injection adversary a reusable target. Randomness standards such as FIPS 140-3 and SP 800-90A govern classical modules, but nothing yet audits the randomness inside quantum error correction.

III · Q-GEAR
Layer one: simulation. Q-GEAR, published at ICPP 2025 with Jan Balewski from NERSC, is the framework that lets a Qiskit circuit run on NVIDIA GPUs at Perlmutter scale without a rewrite. This chapter answers RQ1.
Problem

Same circuit, new hardware, no rewrite

Researchers write Qiskit. The fast simulators want something else.

CPU BASELINE

2× AMD EPYC 7763

128 cores, 512 GB. A 34-qubit random circuit takes about 24 hours in a state-vector simulation.

GPU SIMULATORS

Fast, but fragmented

CUDA-Q kernels, Qiskit Aer GPU and PennyLane Lightning each want their own program, environment and job script.

GOAL

Transform, containerize, scale

Keep the Qiskit program; generate CUDA-Q kernels automatically; ship the stack as Podman/Shifter containers for Slurm on Perlmutter.

III · Q-GEAR
The starting point is practical. Our baseline CPU node, two EPYC 7763 processors with half a terabyte of memory, needs a day for a 34-qubit random circuit. GPU simulators are much faster, but each expects a different program. Q-GEAR's goal is to keep the Qiskit program and automate the rest.
Design

Circuits become three tensors

Gate set currently supported by the transformer: H, RY, RZ, U3, CX, CP, SWAP and measurement.

III · Q-GEAR
The transformation starts by flattening the circuit into three aligned tensors: which gate, which qubits, and which angles. The encoding is stored in HDF5, so the same file can drive a CPU run, a single-GPU run, or a thousand-GPU run. From it we generate a CUDA-Q kernel automatically for the gate set shown at the bottom.

III · Q-GEAR
End to end, the pipeline has six stages, and Q-GEAR automates the four in the middle. The two highlighted stages, encoding and kernel generation, are the contribution; packaging in Podman or Shifter containers is what makes the result reproducible on Perlmutter's Slurm scheduler.
Deployment

One node to a thousand GPUs

III · Q-GEAR
Each Perlmutter GPU node has four 40-gigabyte A100s connected by NVLink, and CUDA-Q's multi-GPU backend shards the state vector across them. Beyond one node, MPI over the Slingshot interconnect lets us aggregate memory across nodes: 256 nodes give 1,024 GPUs, which is where the 42-qubit runs happened at close to full GPU utilization.

IV · DEAL & QAWA
Layer two: algorithms on noisy hardware. Two papers: DEAL, published at IEEE QCE 2025, replaces black-box QAOA angle search with a direct mapping from the problem; QAWA proposes a data-traceable oracle so that QAOA outputs can be interpreted without tomography. Both answer RQ2.
Problem

QAOA treats the device as a black box

IV · DEAL & QAWA
Vanilla QAOA searches its angles by repeatedly running the circuit and handing the expectation value to a classical optimizer. Every iteration costs shots times depth, the landscape is flat in places, and none of this uses what we know about the problem coefficients or the device. On Heron the twenty-qubit circuits stop improving after roughly forty CZ gates, so depth is a hard budget.
DEAL · Direct Entanglement Ansatz Learning

Read the angles off the problem

Direct angle mapping

Cost- and mixer-Hamiltonian angles are computed from the QUBO coefficients instead of searched by an optimizer.

Entanglement-based ansatz

Echoed cross-resonance gates arranged for maximal entanglement within the CZ budget of the device.

Adaptive digital ZNE

Delay and identity gates control crosstalk and coherence errors; a Bayesian search picks the layer count.

IV · DEAL & QAWA
DEAL has three parts. First, the angles are read directly off the QUBO coefficients, so there is no optimizer loop on hardware. Second, the entangling structure is chosen for the device, using echoed cross-resonance gates. Third, an adaptive digital zero-noise extrapolation cleans up the result. The circuits are twenty qubits and up to ten layers on the Heron processors Torino and Marrakesh.
DEAL · Error mitigation

Adaptive zero-noise extrapolation

Chart is a schematic of the extrapolation; DEAL reports its accuracy with the QNRE metric and picks layers by Bayesian optimization.

IV · DEAL & QAWA
Digital ZNE runs the same logical circuit at several noise scales by inserting identity or delay gates, then extrapolates the expectation value back to zero noise. The adaptive part is that the insertion pattern targets crosstalk and coherence, the two dominant error sources on these devices. We quantify the residual with a quantum noise-limited relative error and choose the number of layers by Bayesian optimization.
Results · hardware

DEAL beats vanilla QAOA on Heron-1

20-qubit, 10-layer circuits; success = reaching the ground-state energy. DEAL also shows lower error variance. Near-optimal ground energies for TSP, knapsack and MaxCut instances (Table II optima 8.795/7.468, 39.167, 14.184).

On the right, the depth trade: DEAL at seven layers matches what QAOA needs nine layers for, which matters because each layer spends part of the forty-CZ budget.

QAWA · Quantum Approximate Walk Algorithm

A data-traceable oracle in O(n) depth

The oracle keeps a classical trace of what the circuit encodes, so QAOA outputs become interpretable without tomography, and solution quality is verifiable in polynomial time. Simulations extend to 20 qubits.

IV · DEAL & QAWA
QAWA attacks interpretability. Reading n-qubit correlations by tomography costs order n-squared measurement settings. The QAWA oracle instead grows linearly in CNOT depth with the qubit count and keeps a classical trace of what it encodes; mid-circuit measurement data are preprocessed classically and fed back into the next shallow circuit. The result is a walk that learns approximate solution patterns whose quality can be verified in polynomial time.

V · Quantum learning
Layer three is the data interface, and it is the largest chapter: four papers. QPIE is a hybrid network published in Quantum Science and Technology; VQT is a quantum transformer from the AAAI Symposium Series; ShardQ cuts and knits encoding circuits; and NNQA compiles trained polynomial networks into exact quantum arithmetic. All four answer RQ3.
Problem

Getting data in and out is the cost

RQ3 asks for encodings that are shot-efficient, hardware-compatible and trainable — at the same time.

SHOT-EFFICIENT

Reading out costs shots

Every estimated value carries shot variance p(1−p)/S. Attention over B sequences of length T means B·T² values; estimating them one by one does not scale.

HARDWARE-COMPATIBLE

Loading costs depth

A vectorized QCrank loader needs Θ(N) CNOTs for N values. On Heron hardware with ≈1.5×10⁻³ CZ error, deep loaders must be cut, compiled and mitigated.

TRAINABLE

Gradients must exist

Barren plateaus and black-box ansätze make training fragile. We want encodings whose parameters come from classical training or have learnable, well-conditioned heads.

V · Quantum learning
The data interface has three requirements that pull against each other. Readout costs shots, loading costs circuit depth, and training needs gradients that do not vanish. The four papers in this chapter each take one corner of that triangle, and they share one building block: the QCrank vectorized encoding, which I will show first.
Building block

QCrank: vectorized data encoding

Address qubits (Hadamards) index the values; data qubits carry them as rotation angles. Used in Q-GEAR benchmarks, QPIE, VQT, ShardQ, QAWA and the nonlinear-wave loader. Experiments span 2–9 address and 2–8 data qubits; a 1,000-pixel image uses 9 address + 2 data qubits.

V · Quantum learning
QCrank, due to Balewski and colleagues at Berkeley Lab, is the encoding this chapter builds on. Address qubits in uniform superposition index the values; each data qubit carries two-to-the-n-a values as rotation angles through a uniformly controlled rotation. The circuit is linear in the number of values and processes all addresses in parallel, which is what makes vectorized arithmetic possible. A thousand-pixel image needs nine address and two data qubits.
QPIE · Quantum Parallel Information Exchange

A non-sequential hybrid network

V · Quantum learning
QPIE is a hybrid network in which the pretrained classical parameters are fed in parallel into several variational circuit blocks, and information is exchanged between the quantum and classical branches rather than stacked sequentially. The gradient rule switches with the backend: parameter shift on real QPUs, adjoint differentiation on GPU simulators, which was up to thirty times faster. Circuits reached 28 qubits.
QPIE · Results

Higher accuracy on every benchmark

Also: ≈88% faster convergence within 100 steps on stochastic time series (NARMA5/NARMA10); Fisher-information eigenvalues up to ≈16 vs ≈7 for classical transfer learning (a less biased spectrum).

V · Quantum learning
On four benchmarks QPIE beats the classical transfer-learning baseline: the ranges are over repeated runs. The largest gains are on the harder sets, brain-tumor MRI and MNIST, where the baseline sits at 0.76 and 0.81. On stochastic time series the model converged about 88 percent faster within a hundred steps, and the Fisher-information spectrum is less biased, which is our explanation for the trainability.
VQT · Vectorized Quantum Transformer

Two shot-efficient primitives

V · Quantum learning
VQT replaces classical self-attention with two primitives built on the same vectorized encoding. The vectorized quantum dot product estimates the whole masked attention matrix at once, with a shot cost logarithmic in the batch-times-sequence-squared size instead of linear. The vectorized nonlinear encoder makes the encoding learnable through a tanh projection head and an expressive quantum head. Attention error stays under 1.2 percent with three million shots, and the appendix proves a variance bound.

V · Quantum learning
ShardQ makes the loader hardware-compatible. The deterministic SparseCut algorithm chooses gate cuts using physical qubit distance and calibrated error rates; sub-circuits are compiled with a bounded-bond-dimension MPS compiler; and the outputs are knitted back with a global quasi-probability reconstruction rather than pairwise. On Heron this cuts RMSE by about fifteen percent and lifts image-encoding fidelity from 0.79 to 0.90. The knitting itself is HPC work: two cuts take fifteen seconds on one A100, four cuts a day on four GPU nodes.

V · Quantum learning
NNQA closes the trainability corner by not training on the QPU at all. A polynomial neural network is trained classically on Perlmutter, then compiled exactly into native unitary blocks for weighted sums and products on real-valued encoded states. A degree-6 polynomial needs seven qubits, five CNOTs and depth nineteen, run once, where VQE needs hundreds of executions. On Heron-3, Nighthawk and IonQ Forte-1 it holds above 99.5 percent accuracy up to degree 35, and we prove a universal-approximation theorem for the construction.
Takeaway

RQ3: vectorize, then learn

  • One encoding, four uses. QCrank-style vectorized loading underlies QPIE's blocks, VQT's attention, ShardQ's cut circuits and NNQA's arithmetic.
  • Shot-efficient: VQDP costs O(log(B·T²)·shots) instead of O(B·T²·d); NNQA runs a polynomial once with 4,096 shots.
  • Hardware-compatible: ShardQ's hardware-aware cuts lift fidelity 0.79 → 0.90; VQT and NNQA ran on IBM Heron, IonQ Aria-1 and Forte-1.
  • Trainable: QPIE's information exchange and VQT's learnable heads keep gradients alive; NNQA removes on-device training altogether.

RubriQ · Rubric-guided GRPO

Synthesis as code generation

VI · Synthesis & cost
RubriQ frames fault-tolerant synthesis as code generation. A seven-billion-parameter coder with LoRA adapters proposes circuits; they are parsed, simulated with CUDA-Q on the GPU, scored by a rubric, and the policy is updated with Group Relative Policy Optimization, which compares eight samples against each other instead of learning a value network. Training runs on Perlmutter with DeepSpeed across up to eight A100 nodes at 85 percent strong-scaling efficiency.
RubriQ · The reward

A programmatic, grounded rubric

VI · Synthesis & cost
The reward is the contribution. Each of the five terms is a program: fidelity from the CUDA-Q simulation carries 40 percent of the weight; Clifford correctness 20; topology compliance and T-gate count 15 each; efficiency 10. Because the rubric is dense and grounded, the policy gets a signal on every sample, which is why it converges two to three times faster than sparse-reward RL with two to three times fewer simulator calls.

Measure, update, reload — every step

VI · Synthesis & cost
The second paper asks what it costs to simulate the nonlinear Schrödinger and viscous Burgers equations when the nonlinearity needs the field values themselves. Instead of hiding that in a linear embedding, we build a hybrid Strang split-step solver that measures the field, updates it classically with a degree-d polynomial, and reloads it with the vectorized loader at every step. Shots, gates and truncation all live in one cost-and-error model, with a controller that keeps the nonlinear phase per step below one.

VI · Synthesis & cost
The conclusion is negative but quantitative. Because every step reads the full field, the quantum cost per step, depth times shots, grows faster than the classical polynomial update as N grows, so the hybrid scheme cannot deliver an end-to-end advantage. What it does deliver is the target: a coherent, measurement-free nonlinear update is what any future advantage claim must beat. Takeaway

RQ4: honest accounting

  • Learned synthesis works when the reward is grounded: a programmatic rubric plus GPU simulation in the loop gives 3.31× T-gate compression with <1% constraint violations.
  • HPC is inside the loop, not beside it: CUDA-Q evaluation (the Q-GEAR path) and DeepSpeed training on Perlmutter make the RL feasible.
  • Count everything: with measurement and reload charged at every step, direct nonlinear-wave simulation has no end-to-end advantage; the model says exactly what a coherent update must achieve.
  • Both results are stated as budgets, T-gates and shots × depth, which is the currency fault-tolerant machines will charge in.

VII · QEC audit
Layer five: trust. This chapter, with coauthors from Lightrider and Quantropi, treats the error-correction encoder on a shared cloud QPU as a security surface and asks how randomness should be used and audited. It is the first half of the answer to RQ5.
Threat model

A public encoder is a reusable target

VII · QEC audit
The setting is a shared cloud processor: your error-corrected job runs next to a co-tenant who can inject a single Pauli fault. If the encoder circuit is fixed and public, the adversary can learn exactly which physical fault produces a harmful logical action that the syndrome check will not catch, and reuse it every run. If the encoder is reseeded per run, the fault has to be chosen before the seed is known. The fault model is deliberately bounded: weight-one Paulis, all three-n locations enumerated.
Definition

Accepted logical disturbance

The accepted logical disturbance of an encoder under a fault is the acceptance-weighted measure of the harmful logical action that survives syndrome-based rejection: faults that are rejected do no harm, faults that are accepted and act trivially do no harm, and only accepted faults with non-trivial logical action count.

BASELINE

Haar-random encoders

We derive the exact expectation of the disturbance for a Haar-random encoder, which is the ideal but exponentially expensive reference.

SUBSTITUTE

Seeded Clifford ensemble

A polynomial-cost Hadamard-structured ensemble (HSE) is sampled from a seed and audited against the same measure.

AUDIT

Two adversary orders

Fault chosen after learning each encoder (fixed) versus fault fixed before the seed is drawn (reseeded).

VII · QEC audit
The central definition is accepted logical disturbance. It weights harmful logical action by the probability that the syndrome check accepts the run, so a fault that is caught costs nothing and a fault that slips through with trivial action costs nothing. We derive its exact expectation for Haar-random encoders as the reference, and then audit a cheap, seeded Clifford ensemble against the same measure under the two adversary orders.
Hadamard-structured ensemble

Seeded structure instead of Haar

VII · QEC audit
The Hadamard-structured ensemble is built from a seed: Hadamard, phase, permutation and CNOT layers, repeated to depth d, all Clifford and therefore cheap to sample and simulate. Not every sample is a valid encoder; 18.5 percent of the sampled circuits satisfy the exact error-correction conditions for the code, and those are the ones the audit uses. The seed is the only secret, which is what connects this chapter to the cryptography module in the next.

Why the quantum stack needs PQC

Our machine breaks its own keys

THE THREAT

Shor’s algorithm

Factoring and discrete logarithms fall to a large fault-tolerant machine; Gidney and Ekerå estimate 2048-bit RSA in 8 hours with 20 million noisy qubits. Every layer of this stack is a step toward that machine.

THE CHANNEL

Cloud QPU jobs are classical traffic

Circuits, calibration data, seeds and results travel over classical networks to IBM, IonQ and HPC centers; they need post-quantum key exchange and signatures now, before the keys can be harvested.

THE LINK TO CHAPTER VII

Seeds need a validated source

Reseeded encoders are only as good as their randomness: the seed must come from an approved DRBG (SP 800-90A) inside a FIPS 140-3 boundary, and the encoder that ran must be attestable.

VIII · Post-quantum stack
Three reasons the quantum stack itself needs post-quantum cryptography. The machines we are scaling toward are the ones that break RSA and elliptic curves. Cloud quantum jobs are classical network traffic that can be harvested today and decrypted later. And, most directly, the reseeded encoders of Chapter VII are only as trustworthy as the random-bit generator and the module boundary behind them.
QPC SDK

One boundary for keys and seeds

VIII · Post-quantum stack
The module implements the three 2024 NIST standards, ML-KEM for key encapsulation and ML-DSA and SLH-DSA for signatures, together with an SP 800-90A random-bit generator, self-tests and a module-search feature for discovering and selecting algorithms. Two consumers matter for this dissertation: signed and encapsulated jobs to cloud QPUs, and DRBG seeds for the reseeded encoders of Chapter VII. It is a 1.1-megabyte Linux release archived on Zenodo.

Conclusion

Five questions, five answers

01 · RQ1 · Scale

Simulation

Scale: exact simulation reaches 42 qubits on 1,024 A100s, ≈400× faster than a CPU node, and the Qiskit program does not change (Q-GEAR).

02 · RQ2 · Noise

Algorithms

Noise: angles read from the problem and ansätze shaped by the device beat black-box search: +14.81 pts, 7 layers for 9 (DEAL); an O(n) traceable oracle (QAWA).

03 · RQ3 · Data

Data encoding

Data: vectorized QCrank-style encodings make learning shot-efficient, hardware-compatible and trainable (QPIE, VQT, ShardQ, NNQA).

04 · RQ4 · Synthesis

Synthesis

Synthesis: rubric-grounded RL synthesizes budget-respecting circuits, 3.31× T-gate compression; honest accounting shows where advantage is absent.

05 · RQ5 · Trust

Trust

Trust: reseeded HSE encoders cut accepted logical disturbance by 86.7%; a FIPS 140-3 PQC module supplies the seeds and signatures.

IX · Conclusion
Back to the stack, now with the answers. Scale: 42 qubits, program unchanged. Noise: structure beats search on real Heron hardware. Data: one vectorized encoding underlies four learning systems. Synthesis: grounded rewards and honest budgets. Trust: reseeded encoders and a validated cryptography module. Together they are the co-designed stack of the thesis statement.
Limitations

What these results do not show

  • 42 qubits is simulation, not hardware. Q-GEAR's scaling is a statement about HPC reach; the largest hardware runs in this work are 20-qubit optimization circuits and 36-qubit arithmetic stress tests.
  • Hardware gains are device- and calibration-specific. DEAL gains 14.81 points on Torino but 7.40 on Marrakesh; VQT's RMSE ranges from 0.059 (Kingston) to 0.155 (Aria-1). Repeats across calibration cycles are limited.
  • Learning benchmarks are small. Moon, Spiral, MNIST and the Brown corpus; VQT remains 12.9 perplexity points behind a 125K-parameter nanoGPT. No quantum advantage is claimed for learning.
  • The QEC audit is at code-capacity scale. The [[5,1,3]] code with weight-one faults, Stim at n = 17; surface-code distances and correlated faults are future work.
  • Six of the ten papers are preprints (ShardQ, QAWA, NNQA, RubriQ, nonlinear waves, QEC audit); their numbers may change in review.
IX · Conclusion
I want to be explicit about limits. The 42-qubit result is simulation. The hardware gains depend on which device and which calibration cycle we hit. The learning benchmarks are small and I claim no advantage there. The security audit is at five-qubit-code scale. And six of the ten papers are still preprints. These are the boundaries within which the answers hold.

DEAL, in pseudo-code

# Direct Entanglement Ansatz Learning (DEAL) — sketch
input  QUBO matrix Q (n = 20), device coupling map, CZ budget ≈ 41–43
output bitstring x*, energy E*

γ, β ← direct_map(Q)           # angles from Qᵢᵢ, Qᵢⱼ; no optimizer
p   ← bayes_select_layers(Q, budget)   # 7 layers ≈ QAOA at 9
for λ in noise_scales:                  # adaptive digital ZNE
    C ← entangling_ansatz(γ, β, p, coupling_map)   # echoed cross-resonance
    C ← insert_delays(C, λ)               # crosstalk / coherence control
    E[λ] ← run(C, shots)
E*  ← extrapolate(E, λ → 0)
x*  ← argmin_sample(C)
QNRE ← |E* − E_exact| / noise_limit           # reported metric
INSTANCES

Travelling salesman, knapsack and MaxCut; Table II optima 8.795 / 7.468, 39.167 and 14.184.

VALIDATION

20-qubit circuits were simulated with the Q-GEAR GPU path before submission to IBM Torino and Marrakesh.
